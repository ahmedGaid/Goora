# Android release signing

The keystore and its passwords stay **outside the repo**, in `D:\Secrets\Goora\`.
`android/.gitignore` already ignores `key.properties`, `*.jks` and `*.keystore`. Never commit them.

## How the build finds the key

`android/app/build.gradle.kts` looks for a `key.properties` file in this order:

1. The path in the environment variable `GOORA_KEY_PROPERTIES`.
2. `android/key.properties` (git-ignored; handy on a machine you own).
3. Neither found → the release build is **signed with the debug key**. `flutter build apk --release`
   still works for anyone, but Google Play rejects a debug-signed upload.

Two cases stop the build on purpose, so a store build can never be debug-signed by accident:
- `GOORA_KEY_PROPERTIES` is set but the file is not there.
- `key.properties` exists but one of its four fields is empty or missing.

The app id stays `app.goora.goora`. It cannot change after the first Play upload.

## One-time setup (founder, on the company PC)

1. Make the folder and the key. `keytool` ships with the JDK that Flutter already uses.

   ```powershell
   New-Item -ItemType Directory -Force D:\Secrets\Goora
   keytool -genkeypair -v -keystore D:\Secrets\Goora\goora-upload.jks `
     -storetype PKCS12 -keyalg RSA -keysize 2048 -validity 10000 -alias upload
   ```

   It asks for a password and your name. Use a long password and save it in your password manager.
   With `PKCS12` the key password and the store password are the same one.

2. Back the `.jks` file up somewhere safe (not in git, not on this PC only). Losing it means asking
   Google Play support to reset the upload key.

3. Create `D:\Secrets\Goora\key.properties`:

   ```properties
   storePassword=<the password>
   keyPassword=<the same password>
   keyAlias=upload
   storeFile=D:/Secrets/Goora/goora-upload.jks
   ```

   Use **forward slashes** in `storeFile`. In a `.properties` file a backslash is an escape
   character, so `D:\Secrets\...` would be read wrongly. A relative `storeFile` is resolved
   from the `android/` folder.

4. Tell Gradle where it is, for the current terminal:

   ```powershell
   $env:GOORA_KEY_PROPERTIES = "D:/Secrets/Goora/key.properties"
   ```

   To make it permanent: `setx GOORA_KEY_PROPERTIES "D:/Secrets/Goora/key.properties"`, then open
   a new terminal.

## Build a signed bundle for the Play Store

From the repo root, with the env var set. The app reads its backend settings from `--dart-define`
(see `.env.example`); keep the real values in `D:\Secrets\Goora\`, for example `prod.env`.

```powershell
flutter build appbundle --release --dart-define-from-file=D:/Secrets/Goora/prod.env
```

Output: `build/app/outputs/bundle/release/app-release.aab`.

Every upload needs a higher build number than the last one. It comes from `version:` in
`pubspec.yaml` (`0.1.0+1` → the `+1`), or override it for one build with `--build-number 2`.

An APK for a direct install (no store) is the same command with `apk`:

```powershell
flutter build apk --release --dart-define-from-file=D:/Secrets/Goora/prod.env
```

## Check which key signed it

```powershell
# which config the release variant will use (prints Config: release, or Config: debug when no key).
# gradlew.bat is generated by Flutter, so run one `flutter build` first on a fresh clone.
cd android; .\gradlew.bat :app:signingReport; cd ..

# certificate inside a built bundle or APK; the SHA-256 must match your upload key, not "Android Debug"
keytool -printcert -jarfile build/app/outputs/bundle/release/app-release.aab
```

## Play App Signing

Use Play App Signing (the default for new apps). The key above is only the **upload key**: Google
holds the real app-signing key. Register the upload key's certificate when you create the app in
the Play Console. Store accounts and the first upload are founder work, see
[CHECKLIST.md](CHECKLIST.md).

## iOS

Not signed from this repo or from Windows. An Apple Developer account, a Mac with Xcode, the bundle
id `app.goora.goora` and a provisioning profile are needed. See [CHECKLIST.md](CHECKLIST.md).
